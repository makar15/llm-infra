## Модели LLM, доступные в Cursor

| Модель             | Суть                                  | Когда использовать                                |
|--------------------|---------------------------------------|---------------------------------------------------|
| **composer-2-fast**| Быстрый и дешёвый агент               | Простые задачи, команды, bash, конфиги            |
| **gpt-5.3-codex**  | Оптимизирован под код                 | Хороший баланс цена/качество для кодинга          |
| **gpt-5.4**        | Мощный универсальный                  | Сложные задачи, но дороже                         |
| **Claude Sonnet 4.6**  | Сильная архитектурная модель      | Большие ТЗ, multi-service, поддержка контекста    |
| **Claude Opus 4.6**| Топовая, дорогая                      | Сложнейшие reasoning-задачи                       |
| **auto**           | Cursor сам выбирает                   | Иногда удобно, иногда «жжёт» токены без надобности|
| **premium**        | Максимум качества                     | Дорого, нужно не часто                            |

## Виды агентов в Cursor

| Агент / Режим                     | Когда использовать                                                         | Плюсы                                                              | Минусы                                                |
|-----------------------------------|----------------------------------------------------------------------------|--------------------------------------------------------------------|-------------------------------------------------------|
| **Claude Sonnet** (встроенный)    | Большие архитектурные задачи, генерация multi-file проекта, сложная логика | Отлично держит контекст, генерит связанный код, понимает UML       | Тяжёлый → больше токенов                              |
| **GPT-4o / GPT-5.3** (light agent)| Малые скрипты, команды, Docker, bash, конфиги                              | Быстро, экономно по токенам                                        | Меньше контекста → может упустить связь между сервисами |
| **Cursor «light» agent**          | Рефакторинг и правка уже существующего кода                                | Очень дешёвый, точно делает edits                                  | Не генерирует проект с нуля                           |
| **Cursor «full / auto» agent**    | Генерация с нуля                                                           | Максимальная автономность, меньше ручной работы                    | Ест токены, иногда делает лишнее                      |

## Личные правила выбора для этого проекта

1. **Архитектура / multi-service / docker-compose** → Sonnet 4.6.
2. **Один Go-файл / правка конфига / bash-команда** → composer-2-fast или gpt-5.3-codex.
3. **Когда не знаешь, что выбрать** → начни с Sonnet 4.6, через 2–3 итерации, если задача упростилась — переключись на cheap.
4. **Reasoning / нетривиальный bug** → Opus 4.6 (но дорого, использовать точечно).
5. **Длинные правки по чеклисту / babysit PR** → composer-2-fast / gpt-5.3-codex (быстрее цикл).

## Полезные принципы при работе с Cursor

### 1. Дай контекст, прежде чем просить

Перед «сделай Х» — расскажи, что уже есть. Cursor видит файлы, но не видит **состояние стека / историю решений**. Пример хорошего промта:

```
Контекст:
- Уже работает: postgres + clickhouse + redis + minio + langfuse-web/worker
- В .env есть: POSTGRES_*, CLICKHOUSE_*, ...
- Сеть: llmprojects_backend (external)
- Не ломай существующие healthchecks

Задача: добавить litellm + llmguard + nginx ...
```

### 2. Разбивай большие задачи на этапы

Сразу просить «сделай весь стек» → агент промахивается. Лучше:

- **3A**: storage + Langfuse.
- **3B**: nginx + llmguard + litellm.
- **3C**: dashboard + финальная склейка.

И на каждом этапе — проверка, что предыдущий не сломался.

### 3. Best practices Docker Compose

Финал любого промта про compose:

```
Следуй best practices Docker Compose:
- не используй latest теги
- добавь restart: unless-stopped
- добавь healthchecks
- используй named volumes
- не дублируй env переменные
```

### 4. Фиксируй то, что уже работает

После каждого зелёного этапа — коммит в git с понятным сообщением (`STEP 3A: storage + langfuse setup working`). Это позволяет легко откатиться, если следующий этап что-то сломал.
